# 程式課程審計（Lesson programming audit）

審計日期：2026-10-19 · 對象：全課程庫（L1–L4，共 122 課）· 目的：為「完整幫助系統」清點底數

**重跑方式**（教材每學期會改，這份審計要能重算，不能只留在文件裡）：

```
node tools/audit_lessons.mjs                      # 讀 ../../classfiles 與 ../../local-lab/lab
node tools/audit_lessons.mjs --classfiles <path> --lab <path>
```

輸出：`docs/lesson-audit.json`（機器可讀庫存）＋終端機摘要。

## 一、結論摘要

1. **全庫 122 課，78 課標了〔編程〕**，但其中只有 **20 課**真的有可閱讀的實踐步驟；L2、L3 共 60 課標了編程，卻**一課都沒有數位化的步驟**（搭建與編程圖仍在紙本《搭建步驟圖冊》）。
2. **真正的程式教材只在 L4（32 課）**：10 課在 Wonder Lab、6 課「待建」（沒有起始專案）、16 課靠硬件（UC-Mind 主控板）。
3. **現有步驟全是截圖，沒有一句可朗讀、可搜尋、可示範的文字**。AI 學伴因此無法逐步帶做——它只能回答問題，不能說「現在拖這個積木到這裡」。
4. **「由零開始」的資訊完全不存在**：32 課中 **0 課**說明要匯入什麼角色、設什麼背景；起始專案是預先做好的（1–5 個角色、1–2 個背景）。新手一旦開了空白專案，就無從下手。

## 六、建議的幫助系統結構

三層，全部沿用現有分層（資料／導覽／標註／朗讀／驅動），不加新機制：

**A. 操作參考卡（Knowledge cards）** — 常設、與課題無關，任何時候可查
每張卡：一句用途 → 在界面哪裡 → 三至五步 → 常見錯誤 → 相關課。建議 10 張：
匯入角色、設定背景、切換場景、碰撞偵測、顏色偵測、聲音與音效（標注本版限制）、造型與繪製、變數與清單、座標與移動、分身克隆。

**B. 每課逐步指引（Lesson walkthrough）** — 由零開始
`準備`（開新專案 → 匯入角色 → 設定背景 → 擺位）→ 每個任務的積木步驟（拖哪個積木、填什麼數字、接在哪裡）→ `測試`（按綠旗看什麼）→ `延伸`。
「準備」這一段是全新的：教材沒有，但它正是新手與熟手的分界。

**C. 兩種模式**
- **新手**：全程。`準備`逐步展開並朗讀，每個積木步驟配上圓圈（按哪裡）、箭頭（拖去哪裡）、方格（改哪個輸入）。
- **熟手**：`準備`摺疊成一張清單（「4 個角色、1 個背景」），一鍵跳過直接進積木步驟；仍可隨時展開。
- 選擇記在 localStorage，每課可臨時改；參考卡兩種模式都能開。

**放置位置**：AI 學伴面板的指南分頁再加兩個分頁——「這一課」（按目前課號載入 B）與「操作參考」（A）。逐步步驟沿用現有 `demo` 格式，所以新寫的步驟立刻能被示範、被朗讀、被標註。

**語音成本**：新增文案須跑 `npm run build:voice`，且每句會烘焙三語（粵語／普通話／英語）。10 課全逐步約 600 句 → 1800 個 clip。建議先烘焙粵語，其餘兩語先走瀏覽器語音。

## 七、建議交付次序

1. **第一段**：10 張參考卡 ＋ 5 課逐步（501-bp01、501-bp02、501-bp04、501-bp07、501-bp10）——正好覆蓋你點名的五項關鍵知識（匯入角色、設定背景、切換場景、碰撞、顏色偵測、聲音）。
2. **第二段**：其餘 5 課 Wonder Lab（501-bp03、501-bp13、502-bp03、502-bp06、502-bp09）。
3. **第三段**：6 課「待建」——須先補起始專案才有得寫。
4. **硬件 16 課**：另一條線（UC-Mind），是否納入本幫助系統，需要先定。
