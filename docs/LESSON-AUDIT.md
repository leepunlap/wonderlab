## 一、結論摘要

1. **全庫 122 課，78 課標了〔編程〕**，但其中只有 **20 課**真的有可閱讀的實踐步驟；L2、L3 共 60 課標了編程，卻**一課都沒有數位化的步驟**（搭建與編程圖仍在紙本《搭建步驟圖冊》）。

## 六、建議的幫助系統結構

三層，全部沿用現有分層（資料／導覽／標註／朗讀／驅動），不加新機制：

**A. 操作參考卡（Knowledge cards）** — 常設、與課題無關，任何時候可查
每張卡：一句用途 → 在界面哪裡 → 三至五步 → 常見錯誤 → 相關課。建議 10 張：
匯入角色、設定背景、切換場景、碰撞偵測、顏色偵測、聲音與音效（標注本版限制）、造型與繪製、變數與清單、座標與移動、分身克隆。

**B. 每課逐步指引（Lesson walkthrough）** — 由零開始
`準備`（匯入角色 → 設定背景 → 擺位）→ 每個任務的積木步驟（拖哪個積木、填什麼數字、接在哪裡）→ `測試`（按綠旗看什麼）→ `延伸`。
「準備」這一段是全新的：教材沒有，但它正是新手與熟手的分界。

**C. 兩種模式**
- **新手**：全程。`準備`逐步展開並朗讀，每個積木步驟配上圓圈（按哪裡）、方格（拖去哪裡／改哪個輸入）。
- **熟手**：`準備`摺疊成一張清單（「4 個角色、1 個背景」），一鍵跳過直接進積木步驟；仍可隨時展開。
- 選擇記在 localStorage，每課可臨時改；參考卡兩種模式都能開。

**放置位置**：AI 學伴面板的指南分頁再加兩個分頁——「這一課」（按目前課號載入 B）與「操作參考」（A）。逐步步驟沿用現有 `demo` 格式，所以新寫的步驟立刻能被示範、被朗讀、被標註。

**語音成本**：新增文案須跑 `npm run build:voice`，且每句會烘焙三語（粵語／普通話／英語）。10 課全逐步約 600 句 → 1800 個 clip。建議先烘焙粵語，其餘兩語先走瀏覽器語音。

### 匯入示範不是「背後代勞」

第一版把角色直接塞進 VM：字在說「撳加號」，畫面甚麼也沒有 —— 學生最需要看的那一步（哪個按鈕、哪一格、捲到哪裡）恰好沒示範。現在改成走一次真的路徑：

| 動作 | 畫面 |
|---|---|
| 圈住角色區右下角的加號，標「加角色」 | 光環 |
| 按下，角色庫打開 | 真的開 |
| 在 1715 個圖磚中捲到目標，圈住它（其餘畫面壓暗），標上課本的名字（大象） | 強光環 + 壓暗 |
| 按下圖磚，角色帶著課本的名字落到舞台 | 真的加 |

三個實作上的坑，都寫進了程式註解與測試：

- 角色庫把每件素材畫了五份（343 件 → 1715 個圖磚），其中一些是量度用的幽靈，矩形在可見範圍之外。所以先捲、再看矩形是否真的落在網格內，不合就換下一份。
- `vm.addSprite` / 圖磚點擊的 resolve 值都是 `undefined`，成敗只能看舞台。而角色庫在角色落地之前就關門，所以「關門」才是「按中」的訊號；之後用輪詢等它出現（背景圖大，等 12 秒）。
- 點擊只給角色庫預設名（Mouse1、Elephant），課程積木用的是課本名字（小老鼠、大象），落地後即時改名。

任何一步失敗都會退回直接匯入，最多少了指點，不會少一個角色。

`npm run check:pages` 現在四項：30 個匯入、新手 7 步對熟手 4 步、343 個縮圖、以及一次完整的「指着加號走進角色庫」（圈到加號、圈到圖磚、四個角色以課本名字在台上、背景是剛才選的那張）。

## 十、讀音（2026-10-19）

旁白由 Microsoft Edge 的神經語音烘焙而成，聽落大致準確，但多音字係靠運氣：`guide.motion.a2.body` 一句「裡面嘅積木就會不停重做」，粵語與普通話都讀成「重（輕重）做」。

工具鏈沒有修正的餘地 —— edge-tts 會把傳入的文字轉義再包進它自己的 SSML，`<phoneme>` 進不去；也沒有 per-voice 的詞典可改。唯一的槓桿是文案，所以規矩訂成：**讀錯就換一個讀得對的詞，並記入 `tools/pronunciation.mjs`**，下次不會有人再寫一次。

- 該句改為「不停重複」（zh-Hant）／「不断重复」（zh-Hans）。「重複」正是指南對 loop 積木一貫的用詞，句子讀起來也更貼近孩子的說法。
- `tools/pronunciation.mjs` 是唯一的清單；`check:guide` 與 `build:voice` 都會讀它。前者每次改動都跑，後者在合成**之前**就擋下來 —— 不會為一句已知讀錯的音，花掉整輪烘焙。
- 語音重烘焙：594 句、592 重用、2 句重錄、0 失敗；舊檔自動清走。

`src/_voice-sheet.html` 是這件事的驗收工具：列出三語每一句旁白，點「聽」即播，可搜字。`check:pages` 第五項會確認「每個語言每一句旁白都有錄音」（198/198）。

### 補記：示範的手（2026-10-19）

光環說「這裡」，箭頭才說「按下去」。匯入示範現在有一隻模擬滑鼠：從右下角（學生剛才按「示範」的那一側）進場，移到加號，壓一下，漣漪散開、一聲輕響，然後角色庫才開；進到庫裡再走一次，停在被圈住的那一格上按下去。

- 聲音是合成的，不是取樣檔：帶通濾波的白噪音做「嗒」，快速下墜的三角波做「身」，兩層都在 0.1 秒內收掉。它跟旁白同一個靜音開關 —— 關掉聲音的孩子不是只關掉人聲。
- 壓下去的動畫與音效是**同步**觸發，真正的 `.click()` 在下一格才送：漣漪和按鈕反應要像同一件事。
- 時長不變：箭頭移動用的是原本就存在的停頓（`lead` / `hold`），不是額外等待。八次匯入的總時長幾乎一樣，只是那段時間裡多了一隻手。
- 讀屏與 `prefers-reduced-motion`：箭頭不再飛越畫面，改成直接出現；漣漪保留（它是指示，不是裝飾）。

驗證：`_import-check.html` 現在會數 —— 10 次移動、10 次按下、10 次出聲，漣漪在取樣中被拍到 139 次；再把同一段合成丟進 `OfflineAudioContext` 離線算峰值（0.175，非靜音）。截圖拍不到 0.46 秒的動畫，所以波形與 DOM 才是這裡的證據。

## 十一、畫面跟着句子走（2026-10-19）

上一版把一步分成兩半：先把整段旁白講完，再讓編輯器動。一段話有兩三句時，這就錯了 —— 學生聽到「角色區右下角個加號」時，光環早已在加號上亮了六秒；等他聽完「一個個加」，手才開始動。指的事物與講的話對不上，指得再準也是指晚了。

修法是**句子即節拍**。烘焙時每一句都有起始毫秒（`manifest.json` 的 `cues`），旁白現在把這條時間軸交出來：

```js
var n = voice.narrate([titleKey, bodyKey], { hold: true, from: 1 });
n.at(0);      // 第二句（正文第一句）開口時 resolve
n.ended;      // 最後一個字講完
```

`from: 1` 是因為標題只是報名，真正描述畫面的是正文。示範收到這支鐘（`sync.at(i)`），每個動作等到它所屬的那一句才開始：加號等命名加號那句，第一格圖磚等「一個個加」那句，積木等描述積木那句，綠旗等下一句。句子用完之後的動作不再等 —— 鐘會夾住，不會卡住。

- 旁白與動作**同時**開始，一步在兩者中較晚的一項結束時才結束；`hold` 讓最後一句留在畫面上，動作還在跑時學生仍讀得到。
- 標註（`annotate`）也逐句出現：`cue` 指定第幾句，預設 0。`marks.add()` 只加不清，於是第二句的光環不會抹掉第一句的。
- 角色庫的走法拆成兩半 —— 開庫（那一句）與選格（下一句）。這才是文案本來就在講的兩件事。
- 靜音、沒有聲音、沒有錄音：`narrate` 交出 `null`，`sync.live` 為假，退回舊節奏（標註獨自站 1.5 秒，之後是手自己的停頓）。畫面不會等一句永遠不會來的話。

驗證：新增 `_sync-check.html`。它不靠喇叭 —— 旁白時間軸寫死在測試裡（第 0 句 2500ms、第 1 句 6000ms、最後一字 9000ms），量的是真頁、真角色庫、真手：

```
ring on the plus appeared at 2520ms        ← 第 0 句開口
presses: 3440 plus, 7120 tile, …           ← 加號在第 0 句內、第一格在第 1 句之後
the picture ran inside the words: yes      ← 加號在 3440ms，遠早於 9000ms
the baked clips give the body 2 sentence(s), first at 100ms — usable
```

同一頁另外確認：真 clips 的時間軸與假設的形狀一致（每行一條、每句一格、時間遞增）。`check:guide` 則逐語言檢查每一句正文都有句子軌 —— 沒有句子就沒有節拍，示範會退回「講完才動」。

`npm run check:pages` 現在六項，全部 PASS：30 個匯入、新手 7 步對熟手 4 步、343 個縮圖、指着加號走進角色庫、畫面跟句子、198 句旁白都有錄音。

## 十二、拿走箭頭；光環跟着對話框一起消失（2026-10-20）

兩個缺陷，同一個病根：**指的東西活得比它指的地方久**。

**一、箭頭沒有了。** 舊的標註有三種形狀：圓圈（按這裡）、箭頭（由這裡拖去那裡）、方格（改這個輸入）。箭頭是唯一一種會「跨」的形狀 —— 它由調色板指去畫布、由加號指去角色區，兩端都是推斷出來的座標。箭頭一旦畫出來就與它所描述的一刻分離：對話框開了、畫面換了、學生把積木拖走了，箭頭仍指着原位。而且它與那隻手重複：手是真的走過去、真的按下去，箭頭只是猜。

所以 `arrow()` 與它的幾何（`centre`、`unit`）、CSS 的 `.wl-mark-head`、`check_guide.mjs` 的 `'arrow'` 形狀、四份教材／參考卡／主題裡的六個箭頭標註，全部移除。剩下兩種形狀都是「環着某個存在的東西」：目標不在畫面上就整個跳過，不會畫錯位置。`check:guide` 現在只接受 `square` 與 `circle`。

**二、選完之後，框要即刻消失。** 角色庫的圖磚在一個 modal 裡，按下即關。框原本有自己的計時器（`hold` 900ms），由畫出來那一刻起算；按下時它還剩三四百毫秒，於是鏡頭是這樣：對話框消失 → 框仍在 → 它環住的是編輯器的空白處。那不是「框太慢」，是框在描述一個已經不存在的地方。

現在 `clearPoint()` 與 `tile.click()` 同一個 tick 執行；加號那一下也一樣（框在按下的一刻撤走，而不是等 2.6 秒，讓它隔着暗幕環住對話框底下的加號）。開庫成功時同時 `clearMarks()` —— 這一步自己的標註是環着編輯器家具的，家具已被蓋住，環着它的光環也是錯的位置。

順帶修好一個判準：`_import-check.html` 原本用「庫關着時見到 `.wl-point`」當作「指着加號」的證據，而這條證據正好由上面那個缺陷製造出來 —— 測試是因為 bug 才通過的。現在「指着加號」計的是兩層的聯集（`.wl-point` 或 `.wl-mark.is-on`），另外新設 `stray`：對話框由開變關的那一個取樣，若仍有框，即為殘留。

**驗證**：把修正註釋掉再跑，`_import-check` 印出

```
frames left after a dialog closed: 4 — LEFT BEHIND
frames left after a dialog closed: 1 — LEFT BEHIND
RESULT FAIL
```

修正放回去：

```
plus lit while the library was closed in 8 samples, ringed inside the library in 15
frames left after a dialog closed: 0 — none
frames left after a dialog closed: 0 — none
RESULT PASS
```

`check:guide` 全綠，`check:pages` 六項全 PASS。

## 十三、示範趕得上旁白嗎（2026-10-20）

句子即節拍之後，動作會等句子。但沒有人問過相反的問題：**一句話的時間，夠不夠把那件事做完？**

實測 501-bp01 第一步（四個角色、正文約九秒）：最後一個動作落在 16710ms，最後一個字落在 10029ms —— 畫面比話多演了六點七秒。學生聽完指示，還要望着手慢慢走完剩下的路；那六秒鐘沒有話在解釋。

兩個來源：

1. **等錯了句子。** 第一格圖磚原本等「一個個加」那句（第二句），於是先靜止三點四秒，然後才趕。
2. **每個角色都要重開一次庫。** 開庫、找格、按下、關庫是一整套固定的成本，四個角色就是四套。這一段不可壓。

一度只想手動把那幾步調快。但七課、每課數步、三語合共 264 步；今日調好，下週改一句文案又會漂。所以做成模型，由工具算。

**模型**（`tools/pace.mjs`）。每一步有兩個數：`need` 是動作按 `perform()` 的真實次序加起來的毫秒，`have` 是正文旁白由第一句開口到最後一個字的毫秒。動作拆成零件 —— 開庫前的拍子、按下、彈窗、走到圖磚、圖磚停留、關庫、角色落地、收尾 —— 每件都分「固定底」與「可壓部分」：按下去就是按下去，一秒不能少；停在圖磚上等學生看清楚，則可以縮。

**槓桿一：語速。** 每一行按自己那一步的 `need` 與 `have` 反解速率，夾在 `-5%` 與 `-22%` 之間，寫進 `manifest.json` 的 `rate`。檔名雜湊包含速率，所以重跑 `build:voice` 只會重新合成需要變慢的那幾行，其餘照舊跳過。

**槓桿二：壓縮停頓。** 示範開始時，`squeezeOf` 用剩下的時間除以可壓總量，得出一個比例（下限 0.45），開庫前的拍子、圖磚停留、收尾的呼吸都乘上它。固定成本不動 —— 把「按下」壓短只會變成少按一次。

**槓桿三：加一句。** 兩者都不夠時，答案是**多講一句，不是再慢一點**。已經 `-22%` 仍追不上的步驟，`check:pace` 會說「這一步要加文案」，而不是「再慢些」。這一次加了九句：501-bp01/02/03/07/10/13 與 502-bp09 的第一步各加一句收尾（「加完之後，角色區見到齊晒，就可以開始。」），502-bp09/t1 另補一句過場。

順帶修好一個判準：`gateTile` 由「等第二句」改為 `null` —— 第一格與開庫同屬第一句，硬等下一句只是白等。

**驗證一：算術。** `npm run check:pace`，264 步 × 三語，四項判準：畫面不得活得比話久超過容差；`want` 已到 `-22%` 仍不足即失敗（要加文案）；磁碟上的 `rate` 與所求相差超過 1% 即提示重烘；首個動作溢出下一句超過 250ms 記為備註。現況：

```
[pace] 264 narrated steps, 3 languages
  ok    every step finishes before its narration does
  ok    every body clip is baked at the rate its step asks for
  1 step/language(s) are read slower than the base rate; slowest -12%
[pace] PASS
```

**驗證二：真頁。** `src/_pace-check.html` 在真旁白、真手、真角色庫之下播三種步：四個角色與九秒文案、四個角色與最短文案、單一背景。量的是最後一個動作與最後一個字之間的差：

```
501-bp01/1  last action 13670ms vs last word 14745ms  → -1075ms
501-bp02/1  last action 15320ms vs last word 12558ms  → +2762ms
501-bp03/2  last action  4120ms vs last word  5699ms  → -1579ms
```

501-bp02 那 +2762ms 由角色庫解碼造成（該步要換場景，前一個專案被重置），測試會把它標成「a stall — the library, not the pacing」，而不是節拍問題。

量測本身也修了三處：計數器是累加的，每案要記基線；角色耐心由 4000ms 放寬到 6000ms，否則會在邊緣被判未落地而重複匯入；建積木的案例移除 —— headless 之下 `getScripts`、`_scripts`、`_blocks` 都是 0，量不到不等於沒有，交由 `check:pace` 的算術與 `_import-check` 覆蓋。

`npm run check:pages` 現為七項，全部 PASS。

## 十四、綠旗也要由手按下（2026-10-20）

整個示範裡，只有一個動作是「無人做的」：綠旗。文案說「按一下綠旗」，畫面在綠旗上畫一個環，然後舞台自己動起來 —— 環住一個沒有人按的按鈕，學生看到的是示範者替他按了，而那正是這隻手要避免的事。這一步本來就無手，也就無從示範。

修法：`pressFlag()` 走與按加號同一條路。手移到綠旗、壓下去、起漣漪與聲響，`vm.greenFlag()` 在同一個 tick 啟動專案。不走 DOM click —— `vm.greenFlag()` 正是按鈕本身所呼叫的函式，走 GUI 的處理器會與 `settled()` 搶時間；借用按鈕的只是它的位置。

連帶三處：

- **手可以趕，但不可省。** `squeezeOf()` 多收一個 `run`：走到綠旗的 660ms 可壓，按下那 90ms 不可。`tools/pace.mjs` 同步新增 `flag` 成本（750/390），並把「走到綠旗」算進 demand —— 它是這一步最後要展示的東西，不是酬勞；酬勞是之後跑起來的程式。綠旗步因此收緊，`502-bp03/t3`（zh-Hans）由 `-12%` 降到 `-17%`，其餘仍及格。
- **一個按鈕不要三個指頭。** `motion/a1` 原本同時有「綠旗」的圓環標註與 `point: 'flag'`。手既然真的按下去，兩個靜態的指頭一併移除，只留手。
- **切場景不加手，因為無處可按。** 換背景是 `add_backdrop`，本來就走角色庫那隻手；而舞台被重建（`prepare()` 重置專案）是嚮導自己做的事，畫面上沒有任何人按過任何東西。在這裡加手是演戲，不是示範。

驗證：`_pace-check.html` 新增第四案 `motion/a1`，要求兩件事 —— 按下的那一刻，箭頭尖端**在綠旗按鈕之內**（`yes, on the button`）；以及程式真的跑了（`x -200 → -190`，`move 10` 的位移）。只驗「有按過」不夠：一個按在別處的 Press 同樣會增加計數。

同時把這一頁的判準由「最後一個動作」收窄為「**手**的最後一個動作」。角色落地是角色庫在抓圖：機器一忙就遲幾秒，而手早已做完 —— 把節拍記在它頭上，會令這一頁為課程改不了的事情而失敗。落地時間照印，並且與停頓一樣標明「the library, not the pacing」；遇到停頓該案豁免。連跑兩次，數字在 −2315ms／+522ms 與 −1115ms／+1242ms 之間浮動，判決一致。

`npm run check:pages` 仍是七項，全部 PASS。

## 十五、拿走「開新專案」那一步（2026-10-20）

每課開頭原本有三步：`p0` 空白舞台、`p1` 匯入角色、`p2` 設定背景。第三步是真的（有手、有按鈕、有圖磚），第二步也是；第一步不是 —— 它只有 `point: 'stage'`，圈住一個空舞台，沒有可按之物、沒有可拖之物，也沒有任何東西會改變。

問題不只是「無聊」。示範本身就是一個新專案，所以「新建一個專案」這件事已經發生過了；剩下的是一句話配一個空畫面。而它是學生看的第一個步驟 —— 第一印象是「指南會把箭頭指向沒有東西的地方」，後面每一步的指認都變得可疑。既然無物可示範，就不要假裝示範。

移除範圍：`opening()` 的 `p0`（十課共用一個函式，故一處）、三語各 20 條文案（十課 × 標題與正文），以及這些行烘出來的 30 支音檔。`p1` 仍帶 `project: EMPTY`，重置舞台照舊 —— 示範本來就從空白開始，只是不再為空白的開場單獨設一步。

連帶修好兩件事，都是移除暴露出來的：

- **測試頁以位置取步。** `_pace-check.html`、`_sync-check.html`、`_import-check.html`、`_shot.html` 都用 `steps[1]`、`steps[2]` 或 `open(topic, 1)` 指步。少一步，它們不會壞，只會安靜地指向旁邊那一步 —— 最壞的一種錯。四處全部改為按 `id` 取（`p1`、`p2`、`a1`），並在註解寫明原因。
- **`build_voice` 沿用了已刪的行。** 舊 manifest 的條目無條件繼承，於是刪掉的行仍留在 manifest、檔案也不會被清。現在只繼承本次仍在朗讀的鍵，其餘交給既有的清理迴圈刪檔。首次執行清掉 33 支（30 支 `p0`，另 3 支是從前累積下來的死條目）。

`check:guide` 89 步、`check:pace` 264 段旁白，皆 PASS；`check:pages` 七項 PASS。
